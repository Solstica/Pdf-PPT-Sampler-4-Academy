# V1.1 — trans: register once, render and publish in one command

Status: implementation specification for the V1.1 release candidate. See README and TEST_RESULTS.md for actual implementation and verification limits. Keep every V1.0 academy command backward compatible.

## User-facing contract

Install an additional console script `trans = academy_sampler.trans:main`. The installed command must be usable from any Bash/Git Bash working directory, without manually activating a course-specific virtual environment.

```bash
trans "/path/to/raw" CM -pre 3
trans CM git@github.com:OWNER/PRIVATE-COURSE-REPO.git
trans --list
trans --show CM
```

The first form registers the source directory under a case-insensitive course code (ASCII letters/digits, canonical uppercase, starts with a letter), assigns stable numbers and safely renames PDF/PPT/PPTX files in place; it does not render, commit or upload. The second form resolves the course from the persistent registry, discovers new files, renders/validates all pages, prepares the private course repository, commits changed allowed files and pushes automatically. Accept SSH and HTTPS GitHub repo addresses. A second argument that looks like a GitHub repository URL selects publish mode, otherwise register mode. Reject ambiguous or invalid arguments. No reliance on current working directory.

Interpret -pre as the five previously tested compression groups, not the existing four preset names:
| -pre | Long edge | WebP quality |
| --- | ---: | ---: |
| 1 | 1920 | 90 |
| 2 | 1600 | 80 |
| 3 | 1280 | 75 |
| 4 | 1024 | 70 |
| 5 | 800 | 60 |

Default 3, method 6, RGB, full page, no OCR. Preserve the existing named inspection preset (2560/Q95) for individual pages via academy. Store chosen preset with course. Accept -pre and --preset-number. Do not reinterpret existing academy named presets. An explicitly changed preset is allowed and recorded.

## Registration and stable naming

Use local per-user state, e.g. ~/.academy-sampler/courses.json and courses/<CODE>/; permit an environment-variable override for tests. Use atomic JSON writes and a per-course lock. Store absolute source/workspace paths only locally. Expose list/show and a clear recovery message for a moved raw folder. Registering an existing code with a different folder is an error unless explicit relocation verifies source identity.

Recursively scan PDF/PPT/PPTX, natural sort relative paths, respect explicit original chapter numbers where possible. Example CM01.pdf, CM02.pptx, CM03.pdf. Keep subdirectories and extension; reserve stable course-wide IDs. Plan all renames first, preserve the original name/relative path/SHA256 in a durable local map, never overwrite, never silently delete duplicates, and never change existing IDs on repeated runs. Reject collisions, changed content under the same ID, symlink escapes and source folders overlapping the tool repository or managed workspace. Use a recoverable journal/two-phase rename when needed, verify SHA256 before/after, and rollback on failure. A dry-run option prints the plan without mutation. If source content changes, require explicit new-version handling; existing referenced IDs must remain stable. New files append the next available ID rather than reordering older ones. Keep original name in all manifests, not only the standardized name.

Reuse V1.0 workspace/registry/renderer/validator/printer/progress. Existing registry and inside() currently assume relative paths inside a workspace. Either safely adapt that boundary to a separately registered external raw root, or use a local managed raw mirror (copy2, hash-verified, not uploaded; document disk overhead). Do not bypass path guards or use Windows symlink privileges as a prerequisite. The external directory is the authoritative original; do not silently overwrite modified sources or lose the original filename map when ingesting standardized names. If mirroring, avoid redundant copying on reruns and validate original as well as mirror hashes. Register even when Office export is unavailable; report inability to determine PPT page count if needed, and block publishing until render/validation succeeds.

## Publish workflow

1. Resolve course and destination, normalize owner/repository. Bind destination to course on first successful publish; different destination requires explicit change. Reject the public tooling repo as a target.
2. Before any course data push, verify target is Private via authenticated GitHub CLI/API (e.g. gh repo view OWNER/REPO --json visibility). Git SSH access alone does not prove privacy. Fail closed if gh missing, unauthenticated, visibility unknown or repository public. Print setup guidance; never change repository visibility or create a public repo automatically.
3. Re-scan registered source directory, append/rename only new files, update source registry. Run existing render and full validate, including pages, actual image sizes and SHA256. Stop before staging/push if any source, export or validation error. Preserve cache on retry. Report office font/hidden-slide warnings; block automatic publishing on page count mismatch.
4. Use a dedicated local publication checkout outside raw and tool source, clone/fetch target (support empty repo), respect default branch, require clean state or safely isolate generated changes. Do not use git add . or git add -A. Never force push, reset, overwrite unknown remote history or auto-resolve conflicts. Verify canonical remote and current head before pushing; fail clearly on concurrent changes.
5. Publish only generated course data: sources/INDEX.md, sources/SOURCE_REGISTRY.md, source_registry.json, index.json, per-document manifests and manifest-listed page images; course config with no absolute local paths, relevant protocol/AGENTS templates, initial review skeleton and reports when needed. Preserve user/AI-authored review files, progress, order and print lists already in destination. Initialize those templates only if absent. Separate publication gitignore from V1.0 local defaults (which ignore sources/review); explicit allowlist is mandatory, including staged path checks. Never publish raw PDF/PPT/PPTX, print PDFs, absolute local paths, environment/credential files, or private course registry. Check remote existing source IDs and hashes for conflicts; do not silently replace them. No automatic deletion of old remote files.
6. Commit only when actual content changes. Ignore volatile timestamps in no-op detection or preserve generated bytes on unchanged runs. Push the chosen branch using ordinary git, report commit SHA and URL. On push failure preserve recoverable local commit and return nonzero; next run can resume without re-render. Repeated unchanged publish should produce no commit. Do not log credentials or embed tokens in URLs.

## Acceptance tests

Extend pytest with synthetic sources and mocked GitHub privacy checks; use a local bare Git remote for integration tests (no real course data or public network publishing). Test:
- install exposes both academy and trans; Windows Git Bash, PowerShell and POSIX shell paths/quoting;
- register with arbitrary CWD, spaces/Chinese path, mixed case extensions, nested folders, natural sort and nonconsecutive new files;
- safe renames, original filename mapping and before/after hashes; collision, duplicate, changed content, crash recovery, repeated registration, code/path mismatch and invalid -pre;
- registry persists across invocations; list/show; 3 and 4 yield correct actual dimensions and quality; 1–5 mappings and inspection remain distinct;
- one-command publish to a new/empty remote and an existing remote; idempotent second publish; append new files; cache; preserve review edits; conflicting IDs/hashes and non-fast-forward;
- failure to validate or privacy unknown/public prevents any push; no raw, credentials, absolute local paths, or extra files staged; push failure recovery;
- V1.0 tests still pass. Office conversion and real authenticated private GitHub push are separate environment-dependent checks, mark untested honestly.

Bump pyproject version to 1.1.0 only when implementation and tests are complete. Update README.md, README_EN.md, AGENTS.md (explicit trans publish is the sole exception to no-auto-push rule; private verification required), docs/LIMITATIONS.md, TEST_RESULTS.md and migration notes. Document pipx installation/global PATH (including Windows Git Bash) and upgrade. No real course data in the public tool repo.
